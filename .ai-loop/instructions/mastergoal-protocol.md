# Autonomous 10x Mastergoal Protocol

Synthesize all independent research rounds into one Farely implementation-ready mastergoal. Map every selected task to the current FLY requirement, FEATURE_CONTRACT entry, GATE/RG gate, user journey, source/provider boundary, and falsifier. Include changed assumptions, exact solutions, affected files/migrations/functions/routes, dependency waves, data/RLS contracts, acceptance criteria, local/staging/production/empirical evidence class, verification commands, rollback, provider-rights constraints and GitHub push. Do not delegate important solution design to the executor. A previous status or certification document is not proof. The goal is long-running and must continue through all justified scope, not stop after a quick build.

The mastergoal must contain explicit `FLY-*` mappings, `GATE-*`/`RG*` mappings,
and a falsifier or negative test for every material claim. The accompanying
`implementation.json` must include `requirements[]`, `gates[]`,
`falsifiers[]`, `evidenceClass`, and wave-level evidence references.
Specify the evidence-ledger entries and maturity level required for each
acceptance claim.
