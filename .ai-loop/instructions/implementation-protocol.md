You have full authority over this Farely repository. Implement the mastergoal, inspect current source and .flycheap state before editing, and do not trust prior completion claims. Preserve migration history, RLS, provider terms, data truth, freshness, risk disclosure and non-goals. Use the applicable project checks: npm run check, npm run check:functions, npm run test:functions, npm run test:e2e, npm run test:integration, focused adversarial/security/migration/performance tests, and git diff --check. Work through every justified wave, repair failures yourself, and verify the real reachable user path. At the start inspect remote and use a dedicated cycle branch; at the end commit complete work, push that branch to GitHub, record exact SHA/environment/evidence freshness, and distinguish local/staging/production/empirical results. If push fails, retry and record failure rather than claiming success. Do not ask for approval. Do not claim completion without current evidence. After reaching a baseline, continue researching only for justified product value or proof improvement, not artificial churn.

Before reporting the cycle, write machine-readable implementation evidence with
`requirements[]`, `gates[]`, `falsifiers[]`, `evidenceClass`, command results,
and source/runtime references. Also append one JSON object per material claim
to `.ai-loop/cycles/<cycle>/evidence-ledger.jsonl` using
`.ai-loop/evidence-policy.json`. A local green test cannot satisfy a staging,
provider-rights, production, or empirical obligation.
